Disposable service chain (steps 35-40; loopback SSH, no UART trace by design)
-----------------------------------------------------------------------------
S98labprobe is a /bin/sh probe service decoded from an echo-safe base64 blob
into /opt/etc/init.d/ (step 35 LAB_SERVICE_READY), never installed on real
routers.  Its state machine: start -> busybox sleep 3600 in background, PID
recorded in /opt/var/run/labprobe.pid, generation counter in labprobe.count;
status -> "RUNNING <generation> <pid>" only if the PID is alive (kill -0);
stop -> kill + pidfile removal; restart -> stop+start (fresh PID, counter+1).

Step-by-step outcomes from report.json (each also requires remote exit 0 and
the echo-safe marker, run.py verify_ssh_response):
- step 35 ssh: PASS (0.58 s)
- step 36 ssh: PASS (0.73 s)
- step 37 ssh: PASS (0.65 s)
- step 38 ssh: PASS (1.07 s)
- step 39 ssh: PASS (0.56 s)
- step 40 ssh: PASS (0.82 s)

Numeric PID values are intentionally not persisted anywhere: the runner keeps
guest output out of reports (secret-safe), and step 40 deletes the pidfiles.
The PID-change proof is the committed on-guest contract in step 39: it exits 0
and echoes RESTART_VERIFIED only if old PID != new PID, kill -0 succeeds on the
new PID (process liveness) and the counter file reads 2 — exactly the
MIPSEL_SERVICE_RESTART chain derived by derive_service_restart_gate.

Persistence scope note (Issue #81 §6): this cycle validates MIPSEL_SERVICE_RESTART
only; it does NOT independently prove post-boot rc.unslung autostart of the
service (MIPSEL_PERSISTENCE, Draft PR #84 stays separate and NOT_TESTED).
