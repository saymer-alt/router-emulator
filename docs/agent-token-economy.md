# Agent token economy — Router Emulator

## Экономия токенов и дорогих QEMU-прогонов — обязательный контракт для ZCode/Codex/Kimi

Адаптация KAS [agent-token-efficiency](https://github.com/saymer-alt/keenetic-auto-setup/blob/main/docs/agent-token-efficiency.md) (issue #420), **без установки плагинов и без обхода safety-gates**. Работает вместе с верхним контрактом и Evidence-first; это правила процесса, а не ограничения качества или разрешение на релиз.

- **Один активный цикл:** определить `Issue/PR | base/head SHA | воспроизводимый FAIL | одна гипотеза | один измеримый следующий результат | STOP`. Не заводить бесконечную очередь агенту, не дублировать соседние PR, максимум три заранее *планируемых* направления. Перед кодом сверить текущие refs и завершённые CI других агентов.
- **Читать адресно:** сначала одну упавшую job, несколько строк вокруг фактического маркера, узкий `lab/<stage>*.py`, тест и GitHub workflow; не скачивать всё дерево QEMU, все UART/SSH-логи, старые дампы и все 30 workflow. Для изменения `lab/ported_e2e.py`, `lab/guest.py`, SSH-протокола, образов, питания, setup/teardown, rollback, `opkg` и security gates — прочесть *полностью один раз на точном SHA* все изменяемые safety-critical файлы и соответствующие контракты. Потом ревью всего diff и связанных тестов. Недостаточный scope чтения не оправдывает пропуск опасного эффекта.
- **Сначала дешёвые проверки:** `python -m unittest lab.test_telemt_ipk`/целевой host-only тест, `python -m compileall -q lab`, lint/контракты нужного файла, проверка точных pins, workflow YAML и path filters. Лишь затем **один целевой** native QEMU прогон на готовом SHA. Не запускать одновременно целую обычную матрицу, если можно сделать узкий dispatch; обязательные release gates при релизе не пропускать.
- **Loop Guard:** две одинаковые безрезультатные попытки при том же SHA/команде/ошибке → изменить гипотезу или собрать новую узкую диагностику, иначе `BLOCKED`. Настоящий transient infrastructure retry можно обосновать отдельно. Не заменять доказательство «ещё одним ночным прогоном».
- **Evidence reuse:** переиспользовать PASS лишь для тех же commit SHA, виртуального образа/Entware lock, профиля, scope и среды. Отличать `HOST PASS`, `QEMU PASS`, `FIELD NOT_TESTED`; mock `opkg` не равен реальному `opkg`, синтетический IPK не доказывает совместимость реального RC. Не менять FAIL/NOT_TESTED на PASS ради экономии.
- **Бюджет ZCode:** небольшая ошибка 1–3M токенов, средняя правка 5–10M, QEMU/Entware расследование ориентир 20–50M, **не квота и не разрешение пропустить обязательные тесты**. Если расход не виден — `NOT_AVAILABLE`; после существенного checkpoint — компактный handoff, а не повторная загрузка логов. Выхлоп: `PR | HEAD SHA | PASS/FAIL/BLOCKED/NOT_TESTED | конкретный run | затронутые файлы | blocker | следующий GO`.
- **Защита среды:** GitHub Actions может быть платным и запускать несколько тяжёлых PR workflow из-за одного изменения. До каждого push проверять event/paths-фильтры; не делать пустые коммиты для перезапуска, не менять workflow permissions/concurrency и не очищать артефакты/образы ради «экономии». Физические роутеры, приватные credentials и продакшен-сети — **вне scope** без отдельного owner GO.

Для TeleMT направляйте агента в [`lab/telemt_ipk_e2e.py`](../lab/telemt_ipk_e2e.py), [host-only тест](../lab/test_telemt_ipk.py), [targeted workflow](../.github/workflows/telemt-ipk-native.yml) и [приёмочную матрицу](telemt-entware-native-e2e.md) **в ветке PR #68**, а не делайте вывод, что эти файлы уже есть в `main`. Состояние извлекается из точного HEAD PR и его последней job, не из старых summary.
